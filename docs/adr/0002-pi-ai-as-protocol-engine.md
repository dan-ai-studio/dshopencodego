# 线协议由插件自带的 pi-ai 副本执行

新插件的适配器自己钉住一份 `@earendil-works/pi-ai`（0.87.x）作为直接依赖，由插件决定升级节奏，而不是复用 Harness 运行时那份。理由：三种线协议的难点不在路由，而在 SSE 解析、工具调用增量、DeepSeek 系 `reasoning_content` 回放、thinking 档位映射与缓存字段——pi-ai 已经踩平这些，且 DSH 自己的 `llm-pi-ai` 用的就是它。插件只管目录、路由、会话头与 UI。

代价与约束：插件因此与 pi-ai 的模型目录 JSON 结构、`Provider`/`Models` 类型和 compat 字段耦合；pi-ai 升级需要跑一遍兼容测试。0.x 语义下 `^0.85.1` 不含 0.86+，所以"跟随 DSH 的 pin"永远拿不到上游修复，这正是必须自带副本的原因。

考虑过并否决：零第三方依赖、三协议自研（可控性最高，但要把上述难点重踩一遍，回归风险与工程量不可接受）；运行时从 CDN 拉 pi-ai 目录 JSON（少一次发版，但引入第三方 CDN 与包内部路径依赖）。
