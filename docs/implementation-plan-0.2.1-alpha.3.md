## 一、通俗背景与核心现状（初中生也能一眼看懂版）

### 1. 它们之间是什么关系？
- **DSH（DeepSeek Harness）**：好比是一台「游戏主机」或者「智能管家平台」。用户电脑里的 DSH 是直接用最新源码跑起来的，版本已经到了 `0.2.1-alpha.3`。
- **dshopencodego（本仓库）**：好比是插在这个游戏主机上的「游戏卡带」或者「扩展插件」。它的作用是帮 DSH 连上 OpenCode Go 的模型服务（比如 `deepseek-v4.1-flash`）。
- **问题所在**：插件清单里写的依赖版本还是旧的（`0.2.1-alpha.2` 和 `cordis@4.0.5-alpha.1`）。当你要安装依赖（`npm install`）时，包管理管家 npm 发现版本要求打架了（也就是报错 `ERESOLVE`），拒绝继续工作。

### 2. 核心结论：业务代码零改动！
经过前序严格的技术审计与实测：
- 代码里调用的所有功能函数、类、接口，新版本里一个都没删，长得完全一样！
- 真正要改的，仅仅是**配置文件里的版本号**、**测试用例的小毛病**、**清理无用配置项**以及**把默认访问网址升级到官方最新地址**。
- **风险等级：极低**。

## 二、四大阶段任务规划（M1 ~ M4 串行执行）

### 阶段 M1：依赖对齐与解开安装阻塞（任务 T-01 ~ T-08）
- **目标**：让 `npm install` 顺畅跑通，三关（类型检查 `typecheck`、代码打包 `build`、单元测试 `test`）全绿。
- **步骤**：
  1. **T-01**：备份当前的 `package.json` 和 `package-lock.json` 到 `scratch/m1-backup/`，记下哈希校验值（保命底牌，随时可回滚）。
  2. **T-02 ~ T-05**：在 `package.json` 中把 cordis 改为 `4.0.5-alpha.2`，19个 `@deepseek-ai/dsh-*` 改为 `0.2.1-alpha.3`，schemastery 改为 `~3.18.5-alpha.2`，补充 peer 依赖兼容。
  3. **T-06**：删除旧的 `node_modules` 和 `package-lock.json`，干干净净全新执行 `npm install`。
  4. **T-07**：运行三关检验，保留原始日志到 `scratch/m1-logs/`。
  5. **T-08**：比对依赖树变化，确认没有意外的包版本漂移。

### 阶段 M2：测试稳定性加固（任务 T-09 ~ T-12）
- **目标**：彻底消灭测试偶发失败（Flake）的问题，保证连续 20 次测试 100% 成功，且测试过程绝对不发真实外网请求。
- **步骤**：
  1. **T-09**：基线复现——先连续跑 20 次测试，记录具体的失败情况与错误日志（不凭空猜测）。
  2. **T-10**：消除真实网络依赖——把测试代码里打向 `models.dev/api.json` 的外网请求换成本地预存的假数据样本（Fixture Mock）。
  3. **T-11**：统一伪造请求（Harness）机制，使用 `vi.stubGlobal('fetch', ...)` 与全局清理成对配对，消除多文件并行时的竞态干扰。
  4. **T-12**：验证成果——再次连跑 20 次测试，必须达到 20/20 全部绿灯退出。

### 阶段 M3：配置与标注清理（任务 T-13 ~ T-14）
- **目标**：扫除配置中的误导信息，保证每个模型配置都有理有据。
- **步骤**：
  1. **T-13**：修正 `src/go-limits.ts` 中 `space-bunny-free` 的限额标注（因为 Go 端点实际根本没有这个模型，实测 400）。
  2. **T-14**：产出用户配置修改建议书 `scratch/m3-profile-advice.md`。严格遵守规范：不私自修改仓库外的用户配置文件，只提供明确改动建议由用户决定。

### 阶段 M4：端点平滑迁移与文档发布（任务 T-15 ~ T-20）
- **目标**：将默认 API 访问网址由旧版 `zen` 升级为官方主推的 `inference`，固化技术决策并升级版本号。
- **步骤**：
  1. **T-15**：修正 `engines.dsh` 范围，使其覆盖 `0.2.1-alpha.*`。
  2. **T-16**：迁移前验证——用真实凭证比对 `zen` 与 `inference` 下的 `/usage` 接口，确认返回的数据格式完全一致。
  3. **T-17**：把 `src/catalog/constants.ts` 中的 `DEFAULT_BASE_URL` 改为 `https://opencode.ai/inference/go/v1`。
  4. **T-18**：撰写技术决策文档 `docs/adr/0006-endpoint-migration-to-inference.md`。
  5. **T-19**：更新总纲文档 `docs/plan.md`，建立清晰的文档指引。
  6. **T-20**：版本号升级为 `v0.1.22`，编写更新日志 CHANGELOG。

## 三、三大开发纪律与安全红线

1. **绝对不碰免费层黑科技**：
   - OpenCode 免费层只允许官方客户端使用（服务端拦截报 `FreeTierError`），伪造客户端有被封禁已付费账号的严重风险。该需求已被彻底否决，坚决不做！
2. **绝对不写外部仓库**：
   - 上游 DSH 核心源码和 OpenCode 源码仅作只读参考，严禁写入修改。
3. **完成必须有真凭实据**：
   - 每一个任务完成必须保留日志，不得把“未跑”当作“通过”。
